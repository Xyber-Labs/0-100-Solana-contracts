\section*{TL;DR}
\begin{itemize}
  \item \textbf{LaunchPool (Per-Wallet Cap):} A deposit pool with a hard per-wallet limit $C$ (e.g., $\le 1$ unit of the base asset) to keep whales from crowding out retail participants.
  \item \textbf{VRF Selection (Overflow Only):} If demand exceeds the hard cap $H$, allocations are decided by verifiably random, uniform sampling over \emph{ticketized} deposits; unselected amounts are automatically refundable.
  \item \textbf{VRF-Timed LP Window:} The creator commits an LP window $[t_{\mathrm{start}}, t_{\mathrm{end}}]$; a VRF draw picks the exact deploy time $t^\ast$ inside the window, reducing coordinated sniping.
  \item \textbf{Fees $\rightarrow$ \$XYBER Buybacks:} Platform fees (target $\phi \ge 90\%$) are routed to market-buy \$XYBER with optional burn share $\beta$ for deflationary pressure.
\end{itemize}

\section*{Introduction}
Open, decentralized token launches often suffer from gas wars, bot sniping, and opaque allocation rules. The Lumi MVP focuses on four primitives—\emph{per-wallet caps}, \emph{VRF-backed overflow selection}, \emph{VRF-timed LP deployment}, and \emph{fee-to-\$XYBER buybacks}—to deliver fairer distributions and reduce adversarial dynamics while staying minimal and auditable.

\section*{Design Principles}
\begin{itemize}
  \item \textbf{Fairness-by-design:} A hard per-wallet cap $C$ and uniform ticket-level selection eliminate gas races and mempool games.
  \item \textbf{Minimal \& auditable:} Small, self-contained programs with deterministic state transitions and explicit authority separation (program-derived addresses).
  \item \textbf{Provable randomness:} Chain-oracle VRF for selection and LP time draws; blockhash-only RNG is \emph{not} used.
  \item \textbf{Transparent economics:} A clear fee policy routes $\ge 90\%$ of fees to \$XYBER buybacks; an optional burn share $\beta$ can permanently reduce supply.
  \item \textbf{Canonical pool commitment:} The launch precommits DEX pool parameters, and the deploy instruction verifies the commitment to prevent fake-pool front-runs.
\end{itemize}

\section*{System Overview (MVP)}
\textbf{Actors:} Contributors, Launch Creators, Lumi Protocol, DEX LP.

\textbf{Lifecycle:}
\begin{enumerate}[label=\arabic*)]
  \item \emph{Create Launch:} The creator initializes a configuration account with $H$, $C$, ticket size $\tau$, LP window $[t_{\text{start}}, t_{\text{end}}]$, and token allocations; a canonical hash of LP parameters is committed.
  \item \emph{Funding Opens:} Wallets deposit the base asset up to $C$; deposits are \emph{ticketized} in increments of $\tau$.
  \item \emph{Selection (if oversubscribed):} A VRF seed drives uniform sampling of tickets up to capacity $K=\lfloor H/\tau \rfloor$; refunds are prepared for unselected amounts.
  \item \emph{Airdrop Assignment:} Approved amounts map proportionally to token allocations; vesting (if any) is enforced by the airdrop vault.
  \item \emph{Randomized LP:} A second VRF draw sets $t^\ast \in [t_{\text{start}}, t_{\text{end}}]$; at or after $t^\ast$, anyone may initialize the precommitted DEX pool via a permissionless instruction.
  \item \emph{Post-Launch Fees:} Fees accrue and are periodically swept to execute \$XYBER buybacks; if $\beta>0$, a portion of purchased \$XYBER is burned.
\end{enumerate}

\section*{Core Mechanics}

\subsection*{Capped Wallet Funding Pool}
Per-wallet cap $C$ is enforced on-chain across multiple deposits while cumulative $\le C$. Deposits are \emph{ticketized} by atomic size $\tau$:
\[
n_i = \left\lfloor \frac{\min(\text{deposit}_i, C)}{\tau} \right\rfloor
\]
with any remainder $< \tau$ held and later refunded if unused. Receipts are issued to each wallet for the number of tickets minted.

\subsection*{Overflow + Randomized Allocation}
If $\sum n_i \cdot \tau \le H$, all tickets are approved. If oversubscribed, define capacity $K = \left\lfloor \frac{H}{\tau} \right\rfloor$ and uniformly sample $K$ tickets without replacement from the multiset of all tickets using a VRF-derived seed. For wallet $i$, the selected tickets $y_i$ define approved amount $a_i = y_i \cdot \tau$ and refund $r_i = \text{deposit}_i - a_i$.

\subsection*{Selection Probability (at least one ticket)}
Let total ticket count be $N$ and capacity $K=\lfloor H/\tau \rfloor$. A wallet with $n_i$ tickets has probability of at least one selection:
\[
\mathbb{P}(Y_i \ge 1) = 1 - \frac{\binom{N - n_i}{K}}{\binom{N}{K}}\,,
\]
following the hypergeometric model with uniform sampling without replacement.

\subsection*{Airdrop of Selected Participants}
Let $A_{\text{airdrop}}$ be the airdrop pool. Each approved wallet $i$ receives
\[
\text{tokens}_i = \frac{a_i}{\sum_j a_j} \cdot A_{\text{airdrop}}\,,
\]
with optional vesting (cliff $T_{\text{cliff}}$ then linear over $T_{\text{vest}}$).

\subsection*{Randomized LP Creation (e.g., Raydium)}
The creator commits an LP window $[t_{\text{LP\_start}}, t_{\text{LP\_end}}]$. A VRF draws $t^\ast \in [t_{\text{LP\_start}}, t_{\text{LP\_end}}]$. Anyone can execute LP deployment at or after $t^\ast$ with precommitted parameters. Initial price is set by the pair ratio:
\[
P_0 = \frac{\text{base}_{\text{LP}}}{\text{token}_{\text{LP}}}\,.
\]
\textbf{Canonical pool commitment:} The launch precommits a hash of LP parameters (token mints, fee tier, initial price ratio, pool program) and the expected pool address derivation. The deploy transaction verifies the commitment before initializing, preventing fake-pool front-runs.

\textbf{Timeout \& fallback randomness:} If the VRF is unavailable or the window elapses without execution, a timeout permits either a repeat draw or a commit-reveal fallback with anti-grinding rules and fixed deadlines.

\subsection*{Built-in Anti-Snipe}
Because allocations are decided before trading, launch-time sniping has limited impact on the initial distribution. Randomized LP timing further reduces coordinated positioning around the deploy moment.

\subsection*{Fee Model \& \$XYBER Buyback}
Let $\phi$ denote the fraction of platform fees routed to \$XYBER buybacks; policy targets $\phi \ge 0.90$. Let $\beta \in [0,1]$ denote the burn share of purchased \$XYBER. Each buyback emits \texttt{BuybackExecuted(amount\_base\_spent, xyber\_bought)} and, if $\beta>0$, \texttt{XyberBurned(amount\_xyber)}. Remaining \$XYBER (if any) recycles to incentives/treasury per pre-declared policy; all parameters and transactions are verifiable on-chain.

\section*{On-Chain Architecture (MVP)}
\textbf{Programs}
\begin{itemize}
  \item \textbf{FundingPool:} Configuration \& state accounts (program-derived) storing $H$, $C$, $\tau$, LP window, status; accepts deposits; mints ticket receipts.
  \item \textbf{RandomSelection:} Requests VRF, samples $K$ tickets, emits approvals, and prepares refunds.
  \item \textbf{AirdropVault:} Holds project tokens; maps approved amounts to token distributions; enforces vesting if enabled.
  \item \textbf{LPDeployer:} Verifies canonical pool commitment; after $t^\ast$, enables permissionless pool initialization via a CPI into the DEX.
  \item \textbf{FeeCollector \& Buyback:} Accrues fees; executes market buybacks of \$XYBER; optional burn; emits accounting events.
\end{itemize}

\textbf{Accounts \& Authorities (Sketch):}
\begin{itemize}
  \item Program-derived authority for FundingPool operations and LP deployment.
  \item Separate authority for FeeCollector to execute buybacks and burns.
  \item Deterministically derived state accounts for per-launch configuration and per-wallet receipts.
\end{itemize}

\section*{Algorithms (Pseudocode)}

\subsection*{Deposit \& Ticketization}
\begin{code}
function deposit(wallet, amount):
  require(state == FundingOpen)
  require(deposited[wallet] + amount <= C)
  deposited[wallet] += amount
  tickets_new = floor(deposited[wallet] / tau) - tickets_issued[wallet]
  tickets_issued[wallet] += tickets_new
  mint TicketReceipts(wallet, tickets_new)
\end{code}

\subsection*{Randomized Allocation}
\begin{code}
function run_selection():
  K = floor(H / tau)
  N = total_tickets()
  if N <= K:
    approve all tickets; finalize
  else:
    seed = get_vrf_seed()    // distinct request id
    winners = sample_without_replacement(N, K, seed)
    for each wallet i:
      y_i = count_winner_tickets(wallet i)
      a_i = y_i * tau
      approve(wallet i, a_i)
      refund_ready(wallet i, deposited[i] - a_i)  // includes < tau remainder
\end{code}

\subsection*{Airdrop Calculation}
\begin{code}
function compute_airdrop(wallet i):
  tokens_i = (approved[i] / total_approved) * A_airdrop
\end{code}

\subsection*{Randomized LP Deployment}
\begin{code}
function schedule_lp():
  (start, end) = LP_window
  seed2 = get_vrf_seed()        // distinct or derived
  t* = start + (seed2 mod (end - start))
  store t*
function deploy_lp():
  require(blocktime >= t*)
  verify_canonical_pool_commit()
  initialize_pool(token_LP, base_LP, price_ratio)
\end{code}

\section*{Parameter Guidance}
\begin{itemize}
  \item Ticket size $\tau$: target 1--5\% of $C$ to balance granularity vs. on-chain state.
  \item Enforce a maximum tickets bound $N_{\max}$ to cap compute/time; any remainder $<\tau$ is refundable.
  \item LP window: 4--24h typical; wider windows reduce coordination risk but delay price discovery.
  \item Refunds: pull-model with a clear claim UI; funds are not reappropriated automatically.
\end{itemize}

\section*{Security \& Risk (MVP)}
\begin{itemize}
  \item \textbf{Verifiable randomness:} Oracle VRF proofs for selection and LP timing; commit-reveal fallback with anti-grinding only as a reserve path.
  \item \textbf{Uniform ticket fairness:} Selection is uniform at the ticket level; contribution helps only up to $C$.
  \item \textbf{Canonical pool commitment:} Precommitted hash and address verification to block fake-pool attacks.
  \item \textbf{Economic guardrails:} Pull-then-claim refunds; bounded instruction compute; deterministic authorities.
  \item \textbf{LP tokens default:} Protocol-owned LP tokens locked for 90 days; custody via multisig; events \texttt{LPLocked}/\texttt{LPUnlocked} emitted.
  \item \textbf{Upgrades \& observability:} Timelocked releases; exhaustive program logs/events; emergency halt path to safe refund-only states.
\end{itemize}
